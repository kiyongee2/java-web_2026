1 프로그램 개요 & 클래스 다이어그램

🎯 학습목표
  • 여러 클래스가 협력하여 하나의 프로그램을 이루는 구조를 이해한다.
  • 각 클래스의 역할(책임)을 구분하고, 클래스 사이의 관계를 UML로 읽을 수 있다.

📖 무엇을 만드는가

  • 은행의 핵심 업무인 계좌 개설 · 입금 · 출금 · 잔액 조회 · 이체를 콘솔에서 다루는 프로그램이다.
  • 실무의 은행 서버도 결국 "계좌(Account)라는 데이터"를 "은행(Bank)이 관리"하는 구조다. 이 예제는 그 뼈대를 가장 단순하게 보여준다.
  • 프로그램은 세 개의 클래스로 나뉜다. 역할을 나누면 코드가 읽기 쉽고 고치기 쉬워진다.
클래스역할(책임)실무에서 대응
Account계좌 한 개의 데이터(계좌번호·예금주·잔액)와 입금/출금 규칙도메인 모델(Entity)
Bank여러 계좌를 보관하고 관리하는 업무 로직(생성·조회·이체)서비스 / 저장소(DB)
BankApp사용자의 입력을 받아 Bank에게 일을 시키는 실행 진입점화면 / 컨트롤러

🧩 클래스 다이어그램 (UML)

BankApp은 Bank를 사용(의존)하고, Bank는 여러 개의 Account를 포함(집합)한다. 즉 "은행 하나가 계좌 여러 개를 가진다".

읽는 법 — 점선 화살표(⇢)는 "A가 B를 사용한다(의존)", 속 빈 마름모(◇)는 "전체가 부분을 보유한다(집합)". 마름모는 항상 전체(포함하는 쪽)에 붙는다.

2 Account 클래스 (계좌)

🎯 학습목표
  • 필드를 private로 숨기고 메서드로만 다루는 캡슐화를 이해한다.
  • 잘못된 입금/출금을 예외로 막는 방어적 코드를 작성할 수 있다.

📖 개념 및 설명

  • 계좌는 계좌번호 · 예금주 · 잔액이라는 데이터를 가진다. 이 값들을 private으로 감춰서(캡슐화) 외부가 잔액을 마음대로 바꾸지 못하게 한다.
  • 잔액 변경은 오직 deposit()·withdraw()를 통해서만 일어난다. 여기서 "0원 이하 금지, 잔액 부족 금지" 같은 규칙을 검사한다.
  • 계좌번호와 예금주는 한 번 정해지면 바뀌지 않으므로 final로 선언한다.
💡 Account.java — 계좌 클래스
package bank;

public class Account {

    private final String accountNumber;  // 계좌번호 (변경 불가 → final)
    private final String owner;          // 예금주 이름
    private long balance;                 // 잔액 (음수가 될 수 없음)

    public Account(String accountNumber, String owner, long initialBalance) {
        this.accountNumber = accountNumber;
        this.owner = owner;
        this.balance = initialBalance;
    }

    // 입금: 0보다 큰 금액만 허용
    public void deposit(long amount) {
        if (amount <= 0) {
            throw new IllegalArgumentException("입금액은 0보다 커야 합니다.");
        }
        this.balance += amount;
    }

    // 출금: 금액이 유효하고 잔액이 충분할 때만 가능
    public void withdraw(long amount) {
        if (amount <= 0) {
            throw new IllegalArgumentException("출금액은 0보다 커야 합니다.");
        }
        if (amount > this.balance) {
            throw new IllegalStateException("잔액이 부족합니다. (현재 잔액: " + this.balance + "원)");
        }
        this.balance -= amount;
    }

    // Getter: 외부에서는 값을 읽기만 가능 (직접 수정 불가 = 캡슐화)
    public String getAccountNumber() { return accountNumber; }
    public String getOwner()         { return owner; }
    public long getBalance()          { return balance; }

    @Override
    public String toString() {
        return String.format("[%s] %s님 / 잔액: %,d원", accountNumber, owner, balance);
    }
}

핵심 — 잔액(balance)은 private이라 외부에서 account.balance = 999 같은 조작이 불가능하다. 반드시 deposit()/withdraw()를 거치므로 "규칙을 어긴 잔액"이 생길 수 없다. 이것이 캡슐화가 데이터를 지키는 방식이다.

3 Bank 클래스 (은행)

🎯 학습목표
  • Map(컬렉션)으로 여러 객체를 키로 저장·조회하는 방법을 익힌다.
  • 여러 계좌에 걸친 업무 로직(이체)을 설계할 수 있다.

📖 개념 및 설명

  • Bank는 계좌들을 Map<String, Account>에 담는다. 키(key)는 계좌번호, 값(value)은 계좌 객체다. 계좌번호로 즉시 계좌를 찾을 수 있다.
  • 실무에서는 이 Map 자리에 데이터베이스(DB)가 들어간다. 저장·조회의 개념은 똑같다.
  • 이체는 "출금 계좌에서 빼고 → 입금 계좌에 더한다". 출금이 실패(잔액 부족)하면 예외가 발생해 입금은 진행되지 않는다.
💡 Bank.java — 은행(계좌 관리) 클래스
package bank;

import java.util.LinkedHashMap;
import java.util.Map;

public class Bank {

    // 계좌번호(key) → 계좌(value). LinkedHashMap: 생성 순서 유지
    private final Map<String, Account> accounts = new LinkedHashMap<>();
    private int sequence = 1;   // 계좌번호 자동 생성용 (110-0001 형태)

    // 새 계좌 개설 → 생성된 계좌를 반환
    public Account createAccount(String owner, long initialBalance) {
        if (owner == null || owner.isBlank()) {
            throw new IllegalArgumentException("예금주 이름을 입력해야 합니다.");
        }
        if (initialBalance < 0) {
            throw new IllegalArgumentException("초기 잔액은 0원 이상이어야 합니다.");
        }
        String accountNumber = String.format("110-%04d", sequence++);
        Account account = new Account(accountNumber, owner, initialBalance);
        accounts.put(accountNumber, account);
        return account;
    }

    // 계좌번호로 계좌 찾기 (없으면 예외)
    public Account findAccount(String accountNumber) {
        Account account = accounts.get(accountNumber);
        if (account == null) {
            throw new IllegalArgumentException("존재하지 않는 계좌입니다: " + accountNumber);
        }
        return account;
    }

    public void deposit(String accountNumber, long amount) {
        findAccount(accountNumber).deposit(amount);
    }

    public void withdraw(String accountNumber, long amount) {
        findAccount(accountNumber).withdraw(amount);
    }

    // 이체: 출금 성공 후 입금 (출금 실패 시 예외 → 입금 진행 안 됨)
    public void transfer(String fromAccount, String toAccount, long amount) {
        if (fromAccount.equals(toAccount)) {
            throw new IllegalArgumentException("같은 계좌로는 이체할 수 없습니다.");
        }
        Account from = findAccount(fromAccount);
        Account to = findAccount(toAccount);

        from.withdraw(amount);   // 잔액 부족이면 여기서 예외 발생
        to.deposit(amount);
    }

    // 전체 계좌 반환 (목록 출력용)
    public Map<String, Account> getAllAccounts() {
        return accounts;
    }
}

핵심 — deposit()/withdraw()가 규칙 검사를 Account에 위임한다는 점에 주목하자. Bank는 "어떤 계좌인지" 찾기만 하고, "얼마를 넣고 뺄 수 있는지"는 Account가 스스로 판단한다. 책임이 깔끔하게 나뉘어 있다.

4 BankApp 클래스 (실행·메뉴)

🎯 학습목표
  • Scanner로 사용자 입력을 받아 프로그램을 제어할 수 있다.
  • try-catch로 예외를 한곳에서 처리해 프로그램이 죽지 않게 만든다.

📖 개념 및 설명

  • BankApp은 사용자와 대화하는 창구다. 메뉴 번호를 입력받아 그에 맞는 Bank의 기능을 호출한다.
  • 업무 로직에서 던진 예외(잔액 부족 등)를 main의 try-catch가 잡아 [오류] ...로 안내하고, 프로그램은 계속 돈다.
  • 뒤에서 Spring Boot 서버로 확장하면, 이 "메뉴 선택(switch)" 부분이 그대로 "URL 요청(REST API)"으로 바뀐다.
💡 BankApp.java — 실행 진입점(main)과 콘솔 메뉴
package bank;

import java.util.Scanner;

public class BankApp {

    private static final Bank bank = new Bank();
    private static final Scanner scanner = new Scanner(System.in);

    public static void main(String[] args) {
        System.out.println("=== 스페이스시엘 은행 시스템 (콘솔 버전) ===");

        // 바로 체험하도록 샘플 계좌 2개 생성
        bank.createAccount("홍길동", 100000);
        bank.createAccount("김철수", 50000);

        while (true) {
            printMenu();
            String choice = scanner.nextLine().trim();

            try {
                switch (choice) {
                    case "1" -> createAccount();
                    case "2" -> deposit();
                    case "3" -> withdraw();
                    case "4" -> checkBalance();
                    case "5" -> transfer();
                    case "6" -> printAllAccounts();
                    case "0" -> {
                        System.out.println("프로그램을 종료합니다.");
                        return;
                    }
                    default -> System.out.println("잘못된 선택입니다.");
                }
            } catch (Exception e) {
                // 업무 로직이 던진 예외를 한곳에서 처리 → 프로그램이 죽지 않음
                System.out.println("[오류] " + e.getMessage());
            }
            System.out.println();
        }
    }

    private static void printMenu() {
        System.out.println("1.계좌개설  2.입금  3.출금  4.잔액조회  5.이체  6.전체목록  0.종료");
        System.out.print("메뉴 선택 > ");
    }

    private static void createAccount() {
        System.out.print("예금주 이름: ");
        String owner = scanner.nextLine().trim();
        System.out.print("초기 입금액: ");
        long initial = Long.parseLong(scanner.nextLine().trim());

        Account account = bank.createAccount(owner, initial);
        System.out.println("계좌 개설 완료 → " + account);
    }

    private static void deposit() {
        System.out.print("계좌번호: ");
        String acc = scanner.nextLine().trim();
        System.out.print("입금액: ");
        long amount = Long.parseLong(scanner.nextLine().trim());

        bank.deposit(acc, amount);
        System.out.println(amount + "원 입금 완료 → " + bank.findAccount(acc));
    }

    private static void withdraw() {
        System.out.print("계좌번호: ");
        String acc = scanner.nextLine().trim();
        System.out.print("출금액: ");
        long amount = Long.parseLong(scanner.nextLine().trim());

        bank.withdraw(acc, amount);
        System.out.println(amount + "원 출금 완료 → " + bank.findAccount(acc));
    }

    private static void checkBalance() {
        System.out.print("계좌번호: ");
        String acc = scanner.nextLine().trim();
        System.out.println(bank.findAccount(acc));
    }

    private static void transfer() {
        System.out.print("보내는 계좌번호: ");
        String from = scanner.nextLine().trim();
        System.out.print("받는 계좌번호: ");
        String to = scanner.nextLine().trim();
        System.out.print("이체 금액: ");
        long amount = Long.parseLong(scanner.nextLine().trim());

        bank.transfer(from, to, amount);
        System.out.println("이체 완료!");
        System.out.println("  보낸 계좌 → " + bank.findAccount(from));
        System.out.println("  받은 계좌 → " + bank.findAccount(to));
    }

    private static void printAllAccounts() {
        System.out.println("=== 전체 계좌 목록 ===");
        bank.getAllAccounts().values().forEach(acc -> System.out.println("  " + acc));
    }
}

6 실습문제 (확장 과제)

🎯 학습목표
  • 배운 구조 위에 새로운 기능을 스스로 얹어 본다.
✏️ 실습문제

실습 1. 계좌 비밀번호 추가하기

Account에 password(String) 필드를 추가하고, 출금·이체 시 비밀번호가 맞아야만 진행되도록 만드세요. 틀리면 예외를 던집니다.

정답 보기 (핵심 부분) 
public class Account {
    private final String password;   // 비밀번호 필드 추가
    // ... 생성자에서 password 도 함께 받아 초기화 ...

    // 비밀번호 확인 메서드
    public void verifyPassword(String input) {
        if (!password.equals(input)) {
            throw new IllegalArgumentException("비밀번호가 일치하지 않습니다.");
        }
    }
}

// Bank 의 출금 - 비밀번호 확인 후 진행
public void withdraw(String accountNumber, String password, long amount) {
    Account account = findAccount(accountNumber);
    account.verifyPassword(password);   // 틀리면 여기서 예외
    account.withdraw(amount);
}
✏️ 실습문제

실습 2. 거래 내역(입출금 기록) 남기기

각 Account가 자신의 거래 내역을 List<String>으로 보관하도록 하세요. 입금/출금/이체 때마다 "입금 +50000 (잔액 150000)" 형태로 기록하고, 조회 기능(7번 메뉴)을 추가합니다.

정답 보기 (핵심 부분) 
public class Account {
    private final List<String> history = new ArrayList<>();

    public void deposit(long amount) {
        // ... 기존 검사 ...
        this.balance += amount;
        history.add("입금 +" + amount + " (잔액 " + balance + ")");
    }

    public List<String> getHistory() { return history; }
}

출금·이체에도 같은 방식으로 history.add(...)를 넣으면 된다.

실습 3. 계좌 종류를 상속으로 나누기 ★

앞 단원(상속·다형성)과 연결해 보자. Account를 부모로 두고, 이자가 붙는 SavingsAccount(적금)를 자식으로 만들어 addInterest()(이자 지급) 메서드를 추가하세요. Bank는 부모 타입 Account로 모두 관리할 수 있어야 합니다(다형성).

정답 보기 (핵심 부분) 
// Account 를 상속한 적금 계좌
public class SavingsAccount extends Account {
    private final double interestRate;   // 이자율 (예: 0.03 = 3%)

    public SavingsAccount(String no, String owner, long init, double rate) {
        super(no, owner, init);      // 부모(Account) 생성자 호출
        this.interestRate = rate;
    }

    // 자식이 추가한 기능: 이자 지급
    public void addInterest() {
        long interest = (long)(getBalance() * interestRate);
        deposit(interest);   // 부모의 deposit() 재사용
        System.out.println("이자 " + interest + "원 지급");
    }
}

// Bank 는 부모 타입으로 담으므로 코드 변경이 거의 없다 (다형성)
Account acc = new SavingsAccount("110-0003", "이영희", 1000000, 0.03);

부모 타입 Account 하나로 일반 계좌와 적금 계좌를 함께 관리하는 것이 다형성이다. addInterest() 같은 자식 고유 기능을 쓸 때만 instanceof로 확인 후 다운캐스팅하면 된다.

7 콘솔 + H2 DB 버전 (JDBC)

🎯 학습목표
  • 메모리(Map)의 한계를 이해하고, 데이터를 DB에 영구 저장할 수 있다.
  • 순수 Java의 JDBC로 DB에 연결해 CRUD를 수행할 수 있다.
  • 이체를 트랜잭션(commit/rollback)으로 안전하게 처리할 수 있다.

📖 왜 DB가 필요한가

  • 앞의 콘솔 버전은 계좌를 Map(메모리)에 담았다 → 프로그램을 끄면 데이터가 모두 사라진다.
  • 실무에서는 데이터를 DB에 저장해 영구 보관한다. 여기서는 설치가 필요 없는 경량 DB인 H2를 사용한다(파일 하나로 동작).
  • Spring 없이 순수 Java의 JDBC로 DB를 다뤄 "DB 접근의 원리"를 먼저 익힌다. 그다음 단계가 Spring Data JPA다.
단계JDBC 흐름사용 클래스

💡 ① Db.java — 연결 & 테이블 생성
package bank;
import java.sql.*;

public class Db {
    // 파일 모드 H2 → 폴더에 bankdb.mv.db 로 저장(데이터 유지)
    static final String URL = "jdbc:h2:./bankdb";
    static final String USER = "sa";
    static final String PASSWORD = "";

    public static Connection getConnection() throws SQLException {
        return DriverManager.getConnection(URL, USER, PASSWORD);
    }

    public static void init() {
        String ddl = """
            CREATE TABLE IF NOT EXISTS account (
                id             BIGINT AUTO_INCREMENT PRIMARY KEY,
                account_number VARCHAR(20) NOT NULL UNIQUE,
                owner          VARCHAR(50) NOT NULL,
                balance        BIGINT      NOT NULL
            )
            """;
        try (Connection conn = getConnection();
             Statement st = conn.createStatement()) {
            st.execute(ddl);
        } catch (SQLException e) {
            throw new RuntimeException("DB 초기화 실패: " + e.getMessage(), e);
        }
    }
}
💡 ② AccountDao.java — JDBC CRUD (일부)
public class AccountDao {

    // 저장 (INSERT) — ? 자리에 값 바인딩(PreparedStatement)
    public void insert(Connection conn, Account a) throws SQLException {
        String sql = "INSERT INTO account(account_number, owner, balance) VALUES(?, ?, ?)";
        try (PreparedStatement ps = conn.prepareStatement(sql)) {
            ps.setString(1, a.getAccountNumber());
            ps.setString(2, a.getOwner());
            ps.setLong(3, a.getBalance());
            ps.executeUpdate();
        }
    }

    // 계좌번호로 조회 (SELECT)
    public Account findByNumber(Connection conn, String no) throws SQLException {
        String sql = "SELECT * FROM account WHERE account_number = ?";
        try (PreparedStatement ps = conn.prepareStatement(sql)) {
            ps.setString(1, no);
            try (ResultSet rs = ps.executeQuery()) {
                if (rs.next()) return map(rs);
                return null;
            }
        }
    }

    // 잔액 변경 (UPDATE)
    public void updateBalance(Connection conn, String no, long balance) throws SQLException {
        try (PreparedStatement ps =
                 conn.prepareStatement("UPDATE account SET balance = ? WHERE account_number = ?")) {
            ps.setLong(1, balance);
            ps.setString(2, no);
            ps.executeUpdate();
        }
    }
}

각 메서드가 Connection을 매개변수로 받는 점에 주목하자. 그래야 이체처럼 여러 SQL을 같은 Connection(하나의 트랜잭션)으로 묶을 수 있다.

💡 ③ BankService.transfer() — 트랜잭션 (핵심)
// 이체 = 출금 UPDATE + 입금 UPDATE (둘 다 성공해야 함)
public void transfer(String from, String to, long amount) {
    Connection conn = null;
    try {
        conn = Db.getConnection();
        conn.setAutoCommit(false);   // ── 트랜잭션 시작 ──

        Account fromA = require(conn, from);
        Account toA = require(conn, to);
        if (amount > fromA.getBalance())
            throw new IllegalStateException("잔액이 부족합니다. ...");

        dao.updateBalance(conn, from, fromA.getBalance() - amount);  // 출금
        dao.updateBalance(conn, to,   toA.getBalance()   + amount);  // 입금

        conn.commit();   // ── 둘 다 성공 → 확정 ──
    } catch (RuntimeException e) {
        rollback(conn);   // 잔액부족 등 오류 → 전체 취소(출금도 되돌림)
        throw e;
    } catch (SQLException e) {
        rollback(conn);
        throw new RuntimeException("이체 실패: " + e.getMessage(), e);
    } finally {
        close(conn);
    }
}
💡 트랜잭션이 왜 중요한가 — 출금은 됐는데 입금 직전에 오류가 나면? rollback()이 출금까지 되돌려서 돈이 사라지는 사고를 막는다. "모두 성공, 아니면 모두 취소(All or Nothing)"가 트랜잭션의 핵심이다. (Spring에서는 이걸 @Transactional 한 줄로 처리한다.)
