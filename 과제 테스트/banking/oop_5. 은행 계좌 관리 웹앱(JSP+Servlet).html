1 개요 — Model 2 MVC

🎯 학습목표
  • Servlet(Controller)·JSP(View)·DAO(Model)로 나누는 Model 2 MVC 구조를 이해한다.
  • Spring이 자동으로 해주던 일을 "직접" 하는 방식을 경험한다.

📖 Model 1 vs Model 2

  • Model 1 : JSP 하나에 화면 + 로직 + DB를 다 넣는 방식. 간단하지만 커지면 뒤죽박죽이 된다.
  • Model 2 (MVC) : 역할을 나눈다. Servlet이 요청을 받아 제어(Controller), JSP는 화면만(View), DAO는 DB만(Model). 유지보수가 쉽다. → 이 교안이 다루는 방식.
구성역할이 프로젝트의 파일
Controller요청을 받아 흐름을 제어AccountServlet (Servlet)
View화면(HTML)을 그림accounts.jsp (JSP)
Model데이터·업무 로직·DBAccount, AccountDao, BankService
💡 이 버전의 의미 — Spring MVC는 요청 매핑·객체 생성(DI)·뷰 렌더링을 자동으로 해준다. 여기서는 그것을 Servlet으로 직접 만든다. 그래서 "Spring이 대체 무엇을 대신해 주는가"를 몸으로 알 수 있다.

2 동작 흐름 (다이어그램)

🎯 학습목표
  • 요청 한 번이 Servlet → Service → DAO → JSP를 거쳐 화면이 되는 과정을 이해한다.

아래 번호 순서로 한 번의 요청이 처리된다. doGet은 조회 후 JSP로 forward, doPost는 처리 후 redirect(PRG)한다.

3 프로젝트 구조 & 의존성

📖 폴더 구조 (Dynamic Web Project)

STS5의 Dynamic Web Project로 만든다(Maven 아님). 소스는 src/main/java, 화면·정적 파일은 webapp 아래에 둔다.

bank  (Dynamic Web Project)
└─ src/main/
   ├─ java/com/example/bank/
   │  ├─ model/Account.java          # Model — 데이터
   │  ├─ dao/Db.java                 # DB 연결·테이블
   │  ├─ dao/AccountDao.java         # Model — JDBC(SQL)
   │  ├─ service/BankService.java    # 업무 로직·트랜잭션
   │  ├─ controller/AccountServlet.java  # Controller (@WebServlet)
   │  └─ listener/DbInitListener.java    # 시작 시 초기화 (@WebListener)
   └─ webapp/
      ├─ index.jsp                   # /accounts 로 이동
      ├─ css/style.css
      └─ WEB-INF/
         ├─ web.xml
         ├─ lib/h2-2.4.240.jar       # H2 드라이버 (여기 넣으면 자동 인식)
         └─ views/accounts.jsp       # View — 화면(스크립트릿)
💡 WEB-INF 규칙 — WEB-INF/ 안의 JSP는 URL로 직접 접근할 수 없다(보안). 반드시 서블릿을 거쳐 forward로만 열린다. 정적 파일(css)은 WEB-INF 밖에 둔다.
💡 라이브러리 (Maven 없이) — 무엇이 필요한가
  • Servlet API : Tomcat v10.1 런타임이 제공한다. 프로젝트 생성 시 Target runtime으로 지정하면 자동으로 잡히므로 따로 넣지 않는다.
  • H2 드라이버 : h2-2.4.240.jar를 webapp/WEB-INF/lib에 넣는다(프로젝트에 포함되어 있음). 배포 시 자동 인식된다.
  • JSTL : 사용하지 않는다. 화면을 1장에서 배운 스크립트릿/표현식으로 작성해, 별도 라이브러리 없이 동작한다.
⚠️ javax vs jakarta — Tomcat 10 이상은 jakarta.servlet.*, Tomcat 9 이하는 javax.servlet.*를 쓴다. 톰캣 버전과 import가 반드시 일치해야 한다. 이 프로젝트는 Tomcat v10.1(jakarta) 기준이다.

4 Servlet — 컨트롤러

🎯 학습목표
  • @WebServlet과 doGet/doPost로 요청을 처리할 수 있다.
  • 조회는 forward, 폼 처리는 redirect로 응답할 수 있다.
💡 AccountServlet.java
@WebServlet("/accounts")   // 이 URL을 이 서블릿이 담당
public class AccountServlet extends HttpServlet {

    private final BankService service = new BankService();

    // 계좌 목록 화면 (GET)
    @Override
    protected void doGet(HttpServletRequest req, HttpServletResponse resp)
            throws ServletException, IOException {
        HttpSession session = req.getSession();
        moveFlash(session, req, "message");   // 세션 flash → request 로
        moveFlash(session, req, "error");

        req.setAttribute("accounts", service.getAllAccounts());   // Model → View
        req.getRequestDispatcher("/WEB-INF/views/accounts.jsp")
           .forward(req, resp);   // JSP로 넘겨 화면 생성
    }

    // 폼 처리 (POST) — action 파라미터로 기능 구분
    @Override
    protected void doPost(HttpServletRequest req, HttpServletResponse resp)
            throws ServletException, IOException {
        req.setCharacterEncoding("UTF-8");   // 한글 파라미터
        String action = req.getParameter("action");
        HttpSession session = req.getSession();
        try {
            switch (action == null ? "" : action) {
                case "create" -> {
                    var a = service.createAccount(req.getParameter("owner"),
                                                 parseAmount(req.getParameter("initialBalance")));
                    session.setAttribute("message", a.getAccountNumber() + " 계좌 개설 완료.");
                }
                case "deposit"  -> { service.deposit(req.getParameter("no"), parseAmount(req.getParameter("amount"))); session.setAttribute("message", "입금 완료."); }
                case "withdraw" -> { service.withdraw(req.getParameter("no"), parseAmount(req.getParameter("amount"))); session.setAttribute("message", "출금 완료."); }
                case "transfer" -> { service.transfer(req.getParameter("from"), req.getParameter("to"), parseAmount(req.getParameter("amount"))); session.setAttribute("message", "이체 완료."); }
                case "delete"   -> { String no = req.getParameter("no"); service.closeAccount(no); session.setAttribute("message", no + " 해지 완료."); }
                default -> session.setAttribute("error", "알 수 없는 요청입니다.");
            }
        } catch (Exception e) {
            session.setAttribute("error", e.getMessage());   // 잔액부족 등
        }
        resp.sendRedirect(req.getContextPath() + "/accounts");   // PRG
    }
}
💡 forward vs redirect — forward는 서버 내부에서 JSP로 넘겨 한 번에 응답(주소 안 바뀜). redirect는 브라우저에게 "다시 이 주소로 요청해"라고 응답(주소 바뀜, 새 요청). 폼 처리 후 redirect하면 새로고침해도 중복 제출이 안 된다(PRG). 이때 메시지는 session에 잠깐 담아 전달한다.

5 DAO · Service — 모델

📖 Model — 데이터와 업무 로직

DAO(Data Access Object)는 JDBC로 SQL만 담당하고, Service는 규칙과 트랜잭션을 담당한다. 이 코드는 앞의 콘솔 H2 버전과 거의 동일하다 — 웹이든 콘솔이든 "은행 로직"은 그대로 재사용된다.

💡 AccountDao.java (JDBC · PreparedStatement)
public Account findByNumber(Connection conn, String no) throws SQLException {
    String sql = "SELECT * FROM account WHERE account_number = ?";
    try (PreparedStatement ps = conn.prepareStatement(sql)) {
        ps.setString(1, no);
        try (ResultSet rs = ps.executeQuery()) {
            if (rs.next()) return map(rs);
            return null;
        }
    }
}
💡 BankService.transfer() — 트랜잭션 (콘솔 버전과 동일)
conn.setAutoCommit(false);          // 트랜잭션 시작
dao.updateBalance(conn, from, ...);   // 출금
dao.updateBalance(conn, to,   ...);   // 입금
conn.commit();                       // 둘 다 성공 → 확정 (실패 시 rollback)
💡 재사용 — 저장 방식(콘솔↔웹)이 달라져도 Account·AccountDao·BankService는 그대로다. 바뀌는 건 "요청을 받는 방법"(Scanner → Servlet)뿐이다.

6 JSP — 화면(뷰)

🎯 학습목표
  • 스크립트릿·표현식으로 서블릿이 넘긴 데이터를 화면에 표시·반복·분기할 수 있다.

📖 JSP 스크립트 요소 (1장 복습)

문법이름의미
<%@ ... %>디렉티브페이지 정보·import 등을 선언
<% ... %>스크립트릿자바 코드 실행(if·for 등)
<%= ... %>표현식값을 화면에 출력
request.getAttribute("accounts")-서블릿이 담아 forward한 값 꺼내기
request.getContextPath()-앱 기본 경로(/bank) — 링크에 사용
💡 WEB-INF/views/accounts.jsp (스크립트릿 버전, JSTL 미사용)
<%@ page contentType="text/html; charset=UTF-8" %>
<%@ page import="java.util.List" %>
<%@ page import="com.example.bank.model.Account" %>
<%
    // 서블릿이 request에 담아 forward한 값 꺼내기
    List<Account> accounts = (List<Account>) request.getAttribute("accounts");
    String message = (String) request.getAttribute("message");
    String ctx = request.getContextPath();
%>

<!-- 결과 메시지: 스크립트릿 if + 표현식 -->
<% if (message != null) { %><div class="msg ok"><%= message %></div><% } %>

<!-- 계좌 목록: 스크립트릿 for 문 -->
<table>
  <% for (Account a : accounts) { %>
    <tr>
      <td><%= a.getAccountNumber() %></td>
      <td><%= a.getOwner() %></td>
      <td><%= String.format("%,d", a.getBalance()) %>원</td>
    </tr>
  <% } %>
</table>

<!-- 입금 폼: 숨은 action 값으로 서블릿이 기능 구분 -->
<form action="<%= ctx %>/accounts" method="post">
  <input type="hidden" name="action" value="deposit">
  <input name="no"> <input name="amount" type="number">
  <button>입금</button>
</form>

name 값(action, no, amount)이 서블릿의 req.getParameter("...")와 일치해야 값이 전달된다. 1장에서 배운 디렉티브·스크립트릿·표현식만으로 작성해 JSTL 라이브러리가 필요 없다.

7 리스너 & web.xml

💡 DbInitListener.java — 시작 시 1회 실행
@WebListener
public class DbInitListener implements ServletContextListener {
    @Override
    public void contextInitialized(ServletContextEvent sce) {
        Db.init();                    // 테이블 생성
        BankService service = new BankService();
        if (service.getAllAccounts().isEmpty()) {
            service.createAccount("홍길동", 100000);  // 샘플 계좌
            service.createAccount("김철수", 50000);
        }
    }
}
💡 web.xml — 첫 화면만 지정 (매핑은 애너테이션이 담당)
<web-app ... version="6.0">
    <welcome-file-list>
        <welcome-file>index.jsp</welcome-file>
    </welcome-file-list>
</web-app>

index.jsp는 /accounts(서블릿)로 리다이렉트만 한다. 서블릿·리스너 매핑은 @WebServlet·@WebListener 애너테이션으로 처리하므로 web.xml에 따로 적지 않아도 된다.

8 실행 (STS5 + Tomcat)

🎯 학습목표
  • STS5에서 Dynamic Web Project를 만들어 Tomcat에 배포·실행할 수 있다.

🛠️ 따라하기 ① 프로젝트 만들기

1장에서 STS5 · Tomcat v10.1 · JDK 21 설치가 끝났다고 가정한다.

  • File → New → Dynamic Web Project
  • 프로젝트 이름 bank 입력 · Target runtime: Apache Tomcat v10.1 지정
  • 다음 진행 → "Generate web.xml deployment descriptor" 체크 → Finish

🛠️ 따라하기 ② 소스·라이브러리 넣기

  • 제공된 src/main/java/...의 자바 파일 → 프로젝트 소스 폴더에 복사(패키지 유지)
  • 제공된 webapp/의 index.jsp·css/·WEB-INF/views/accounts.jsp·WEB-INF/web.xml → 프로젝트 webapp 아래 같은 위치에 복사
  • H2 드라이버 h2-2.4.240.jar를 webapp/WEB-INF/lib에 넣기 (안 잡히면 프로젝트 우클릭 → Build Path → Add JARs)

🛠️ 따라하기 ③ 실행 (Run on Server)

  • 프로젝트(또는 index.jsp) 우클릭 → Run As → Run on Server
  • Tomcat v10.1 선택 → Finish
  • 브라우저: http://localhost:8080/bank/ → 샘플 계좌 110-0001(홍길동)·110-0002(김철수) 표시
💡 컨텍스트 경로 — URL의 /bank는 프로젝트(배포) 이름이다. 루트(/)로 바꾸려면 서버 더블클릭 → Modules → Edit에서 경로를 /로 변경한다. (1장 "포트·컨텍스트 경로 변경" 참고)
⚠️ Dynamic Web Project 항목이 없다면 — STS5에 웹 개발 도구(WTP)가 빠진 경우다. Help → Eclipse Marketplace에서 web developer tools를 설치하고 재시작한다. (1장 참고)

10 실습 · Spring과 비교

📊 직접 하기 vs Spring이 대신 하기

하는 일JSP/Servlet (직접)Spring MVC (자동)
URL → 코드 연결@WebServlet + doGet/doPost 분기@GetMapping/@PostMapping
파라미터 받기req.getParameter("no")@RequestParam String no
화면에 데이터 전달req.setAttribute(...) + forwardModel.addAttribute(...) + 뷰 이름 반환
객체 생성/연결new BankService() 직접DI(의존성 주입) 자동

Spring은 이 "반복되는 배선 작업"을 자동화해 준다. 그 밑바탕이 바로 이 Servlet/JSP다.

실습 2. 한글 인코딩 필터 ★

모든 요청에 setCharacterEncoding("UTF-8")를 자동 적용하는 @WebFilter를 만들어, 서블릿마다 반복하지 않도록 하세요. (Spring이 자동으로 해주는 일을 직접 구현)

힌트 보기 
@WebFilter("/*")
public class EncodingFilter implements Filter {
    @Override public void doFilter(ServletRequest req, ServletResponse res, FilterChain chain)
            throws IOException, ServletException {
        req.setCharacterEncoding("UTF-8");
        chain.doFilter(req, res);
    }
}
