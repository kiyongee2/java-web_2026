1 스프링부트란? (개념 · 특징)

🎯 학습목표
  • 스프링부트가 무엇인지, 스프링 프레임워크와의 관계를 설명할 수 있다.
  • 스프링부트의 4가지 핵심 특징을 구분해 말할 수 있다.

📖 스프링부트(Spring Boot)란?

스프링부트 = 스프링(Spring) + 부트(Boot). 스프링 프레임워크의 서브 프로젝트로 만들어졌으며, 이름 그대로 스프링과 부트의 합성어입니다.

  • 부트(Boot) : "컴퓨터를 부팅한다"는 말처럼 시스템을 바로 사용 가능한 상태로 만드는 것을 의미
  • 웹 애플리케이션을 빠르게 제작·출시할 수 있는 경량 오픈소스 프레임워크
  • 2014년 무렵 출시, 점차 스프링에 비해 사용이 늘어나는 추세

📖 스프링부트의 특징 4가지

특징설명
① 라이브러리 관리 자동화기존엔 Maven/Gradle로 의존성을 직접 관리했으나, 부트는 스타터(Starter)로 특정 기능에 필요한 라이브러리 의존성을 간단히 처리
② 설정의 자동화프로젝트에 추가된 라이브러리를 인지해, 실행에 필요한 스프링 설정을 자동으로 처리(Auto Configuration)
③ 테스트 환경 · 내장 서버(톰캣)JUnit 등 테스트 라이브러리 기본 포함. 톰캣을 내장하여 main() 메소드 실행만으로 구동 → 결과를 빠르게 확인
④ 독립 실행 가능한 JAR운영 서버 배포를 위한 패키징 시 WAR가 아닌 JAR 파일로 패키징 가능
💡 핵심  "복잡한 설정을 줄이고(Auto Config), 톰캣을 내장해 바로 실행되는 스프링" — 이것이 스프링부트의 존재 이유입니다.

2 개발 환경 구축 (JDK · STS4)

🎯 학습목표
  • 스프링부트 개발에 필요한 도구(JDK · STS4)를 설치할 수 있다.
  • 환경 변수(JAVA_HOME · Path)를 설정할 수 있다.
  • STS4에 Web Developer Tools를 추가하는 이유를 설명할 수 있다.
🛠️ 따라하기 ① JDK 설치
  1. 오라클 Java 다운로드 페이지 접속(검색)
  2. Windows → Java SE 21 선택
  3. x64 Installer 다운로드 후 설치
🛠️ 따라하기 ② 환경 변수 설정
  1. 시스템 변수 → 새로 만들기 → JAVA_HOME 생성 (값: JDK 설치 경로)
  2. 시스템 변수 → Path → %JAVA_HOME%\bin 추가
⚠️ 확인  설정 후 명령 프롬프트에서 java -version 으로 정상 설치를 확인합니다.
🛠️ 따라하기 ③ STS4(Spring Tool Suite) 설치

STS4는 스프링부트 개발에 특화된 이클립스 기반 IDE입니다.

🛠️ 따라하기 ④ Web Developer Tools 설치

메뉴: Help > Eclipse Marketplace → web 검색 → Eclipse Web Developer Tools(Java and Web) 설치

⚠️ 설치하지 않으면?  html, css, js 파일 등이 지원되지 않습니다. 반드시 설치하세요.

4 정적 파일 & 정적 페이지 (static)

🎯 학습목표
  • static 폴더의 역할을 이해한다.
  • 정적 HTML 파일과 이미지를 배치하고 브라우저로 확인할 수 있다.

📖 static 폴더란?

src/main/resources/static 폴더에 둔 파일은 컨트롤러 없이도 URL로 바로 접근할 수 있는 정적 리소스입니다. 폴더 경로가 곧 URL 경로가 됩니다.

📁 경로 규칙  static/hello.html → http://localhost:8080/hello.html  (static은 URL에서 생략)
💡 예제 — static > hello.html
<!DOCTYPE html>
<html>
<head>
<meta charset="UTF-8">
<title>hello~</title>
</head>
<body>
    <h2>Hello~ 스프링부트!</h2>
</body>
</html>
http://localhost:8080/hello.html

Hello~ 스프링부트!

📖 이미지 등 정적 리소스

이미지도 static 하위에 폴더로 정리합니다. 예: static/images/time.jpg → /images/time.jpg로 참조.

💡 활용  HTML/CSS에서 src="/images/time.jpg", href="/css/style.css" 처럼 /(루트) 기준 경로로 정적 파일을 불러옵니다.

5 메인 페이지 만들기 (Controller)

🎯 학습목표
  • 컨트롤러로 URL을 매핑하고 View(템플릿)를 반환할 수 있다.
  • 뷰 리졸버(View Resolver)가 View 이름을 실제 HTML 파일로 찾는 원리를 이해한다.
  • templates(동적) · static(정적)을 함께 사용해 페이지를 구성할 수 있다.

📖 컨트롤러를 사용한 URL 매핑

정적 파일과 달리, 동적 페이지는 컨트롤러가 요청 URL을 받아 View 이름을 반환합니다. 뷰 리졸버가 그 이름으로 templates 폴더에서 HTML을 찾습니다.

요청/ 접속
→
Controller@GetMapping("/")
→
return "home"View 이름 반환
→
View Resolvertemplates/home.html
💡 예제 — HomeController.java
import org.springframework.stereotype.Controller;
import org.springframework.ui.Model;
import org.springframework.web.bind.annotation.GetMapping;

@Controller
public class HomeController {

    @GetMapping("/")
    public String home(Model model) {
        // 모델(message)에 문자열을 담아 보내기
        model.addAttribute("message", "Hello~ Thymeleaf!");
        return "home";         // 파일: templates/home.html
    }

    @GetMapping("/time")
    public String time() {
        return "/pages/time";  // 파일: templates/pages/time.html
    }
}
💡 Model  model.addAttribute("이름", 값) 으로 담은 데이터는 Thymeleaf에서 th:text="${이름}" 으로 화면에 출력합니다.

6 스프링 MVC & 컨트롤러 어노테이션

🎯 학습목표
  • 스프링 MVC의 3계층 구조와 각 계층의 어노테이션을 설명할 수 있다.
  • 컨트롤러의 역할과 디스패처 서블릿의 관계를 이해한다.
  • @RequestMapping, @GetMapping, @RestController를 구분해 사용할 수 있다.

📖 계층적 구조 (MVC) 구현 과정

스프링 MVC는 역할별로 클래스를 나눠 계층(Layer)으로 구성합니다. 각 계층은 대표 파일과 역할을 가집니다.

계층구성 요소예시 파일
프레젠테이션 계층컨트롤러(Controller) · 뷰(View)MemberController.java · members.html
비즈니스 계층서비스(Service)MemberService.java
퍼시스턴스 계층모델(Model) · 도메인 객체 · 리포지토리Member.java · MemberRepository.java
Controller요청/응답
→
Service비즈니스 로직
→
RepositoryDB 접근(CRUD)

📖 스프링 MVC의 3계층 구조

계층어노테이션역할
Controller@Controller클라이언트 요청 처리, 화면(View) 반환
Service@Service비즈니스 로직 수행
Repository@Repository데이터베이스 접근, CRUD 처리

📖 컨트롤러란?

스프링부트가 웹에서 사용자 요청을 받으면, 가장 먼저 내장 톰캣 서버의 디스패처 서블릿(DispatcherServlet)으로 전달합니다. 디스패처 서블릿은 요청을 받는 창구 역할만 하고, 실제 처리는 컨트롤러(Controller)가 담당합니다.

요청브라우저
→
DispatcherServlet요청 창구
→
Controller실제 처리
→
View ResolverHTML 응답
📌 @Controller  사용자 요청을 받아 뷰(View)로 보여줄 HTML을 반환하는 클래스를 지정하는 어노테이션. 처리 결과를 뷰 리졸버를 통해 HTML 파일로 찾아 응답합니다.
📌 @Repository  데이터 접근 계층(DAO/Repository)을 나타내는 어노테이션. DB와 직접 통신하는 클래스임을 스프링에 알립니다. 스프링이 자동 감지해 빈(Bean)으로 등록하므로, @Autowired나 생성자 주입으로 바로 사용할 수 있습니다.

📖 @RequestMapping — 요청 매칭 경로 설정

요청 URL과 HTTP 메소드를 컨트롤러 메소드에 연결합니다.

@RequestMapping(value="URL", method=RequestMethod.GET)

// 단축형 (GET/POST 구분이 필요 없을 때)
@RequestMapping("URL")
💡 예제 ① — @RequestMapping (Exam01Controller)
@Controller
public class Exam01Controller {

    // @RequestMapping(value="/exam01", method=RequestMethod.GET)
    @RequestMapping("/exam01")
    public String requestMethod() {
        return "pages/view01";   // view01.html
    }
}
<!-- templates/pages/view01.html -->
<title>RequestMapping 예제</title>
<body>
    <h2>RequestMapping 예제</h2>
    <p>웹 요청 URL은 /exam01 입니다.</p>
</body>
http://localhost:8080/exam01
