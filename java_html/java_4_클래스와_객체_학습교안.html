1 객체지향과 클래스

🎯 학습목표
  • 객체와 객체지향 프로그래밍(OOP)의 개념을 설명할 수 있다.
  • 클래스가 속성(멤버변수)과 기능(메서드)으로 구성됨을 이해한다.

📖 개념 및 설명

객체(Object)는 의사나 행위가 미치는 대상입니다. OOP는 객체를 먼저 만들고 객체 간 상호작용으로 프로그램을 구성합니다. 클래스는 객체의 속성(멤버변수)과 기능(메서드)을 코드로 구현한 설계도입니다.

학생 클래스 예
  • 속성: 이름, 나이, 학년
  • 기능: 수강신청(), 수업듣기(), 시험보기()
💡 예제
public class Student {
    String name;   // 속성(멤버변수)
    int age;
    void study() {  // 기능(메서드)
        System.out.println(name + " 공부 중");
    }
}

2 클래스 정의와 객체 생성

🎯 학습목표
  • 클래스를 정의하고 new로 객체를 생성할 수 있다.
  • 점(.) 연산자로 멤버에 접근할 수 있다.

📖 개념 및 설명

public 클래스와 java 파일 이름은 같아야 하고, 클래스 이름은 대문자로 시작합니다. 객체는 new 연산자로 생성하고 객체.멤버로 접근합니다.

💡 예제
Student s = new Student();
s.name = "홍길동";
s.age = 20;
s.study();
홍길동 공부 중

4 생성자(constructor)

🎯 학습목표
  • 생성자의 역할과 규칙을 설명할 수 있다.
  • 생성자 오버로딩을 활용할 수 있다.

📖 개념 및 설명

  • 생성자는 객체를 생성할 때 호출되며, 이름은 클래스와 같고 반환값이 없습니다.
  • 매개변수 없는 기본 생성자는 생략 시 컴파일러가 자동 생성합니다.
  • 오버로딩: 이름은 같고 매개변수가 다른 생성자를 여러 개 둘 수 있습니다.
💡 예제
public class Student {
    String name;
    public Student() { }                // 기본 생성자
    public Student(String name) {      // 오버로딩
        this.name = name;
    }
}
✏️ 실습문제

실습 4-4. 생성자 만들기

이름과 나이를 매개변수로 받아 초기화하는 생성자를 Student에 추가하세요.

정답 보기 
public Student(String name, int age) {
    this.name = name;
    this.age = age;
}

5 this 예약어

🎯 학습목표
  • this가 자기 자신을 가리킴을 이해한다.
  • 매개변수와 멤버변수 이름이 같을 때 this로 구분할 수 있다.

📖 개념 및 설명

this는 생성된 인스턴스 자신을 가리킵니다. 매개변수 이름과 멤버변수 이름이 같을 때 this.멤버 = 매개변수로 구분하며, this()로 다른 생성자를 호출할 수도 있습니다.

💡 예제
public Account(String owner, int balance) {
    this.owner = owner;
    this.balance = balance;
}

6 정보 은닉(캡슐화)

🎯 학습목표
  • 접근 제어자의 역할을 구분할 수 있다.
  • private 변수를 getter/setter로 다룰 수 있다.

📖 개념 및 설명

접근 제어자접근 범위
public어디서나
protected같은 패키지 + 상속 관계
(default)같은 패키지
private같은 클래스 내부만

멤버변수를 private으로 숨기고 get()/set() 메서드로 접근하게 하는 것이 캡슐화입니다.

💡 예제
private int balance;
public int getBalance() { return balance; }
public void setBalance(int b) { balance = b; }

7 static과 싱글톤

🎯 학습목표
  • static 변수가 인스턴스 간에 공유됨을 이해한다.
  • 싱글톤 패턴의 개념을 설명할 수 있다.

📖 개념 및 설명

static 변수는 프로그램 로딩 시 데이터 영역에 한 번 생성되어 모든 인스턴스가 공유합니다. 싱글톤 패턴은 인스턴스를 단 하나만 만드는 설계 방식(생성자 private + getInstance())입니다.

💡 예제
public class Company {
    private static Company instance = new Company();
    private Company() { }
    public static Company getInstance() { return instance; }
}
