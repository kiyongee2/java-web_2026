1 추상 클래스(abstract class)

🎯 학습목표
  • 추상 클래스의 개념과 사용 목적을 설명할 수 있다.
  • 추상 클래스를 선언할 수 있다.

📖 개념 및 설명

여러 실체 클래스의 공통 특성을 추출해 선언한 클래스가 추상 클래스입니다. 객체를 직접 생성할 수 없고 상속을 통해 사용하며, 자식들의 필드·메서드 이름을 통일하는 목적이 큽니다.

💡 예제 — Animal 추상 클래스
public abstract class Animal {

    void breathe() {
        System.out.println("동물이 숨을 쉽니다.");
    }

    public abstract void cry();

}

추상 클래스로는 왜 new로 객체를 만들 수 없나요? 한 문장으로 설명하세요.

정답 보기

구현되지 않은 추상 메서드를 포함할 수 있어 완전한 객체가 아니기 때문이다. 상속받은 실체 클래스에서 구현한 뒤 사용한다.

2 추상 메서드

🎯 학습목표
  • 추상 메서드를 선언하고 자식에서 구현할 수 있다.

📖 개념 및 설명

추상 메서드는 abstract 키워드를 붙이고 구현부({ })가 없이 선언만 합니다. 이를 상속한 실체 클래스는 반드시 구현해야 합니다.

💡 예제 — ① Cat 클래스 (추상 메서드 구현)

상속만 하고 cry()를 구현하지 않으면 "The type Cat must implement the inherited abstract method Animal.cry()" 오류가 난다. 추상 메서드는 반드시 구현해야 한다.

public class Cat extends Animal {

    @Override
    public void cry() {
        System.out.println("야~ 옹!");
    }

}
💡 예제 — ② Dog 클래스
public class Dog extends Animal {

    @Override
    public void cry() {
        System.out.println("멍멍!");
    }

}
💡 예제 — ③ AnimalTest (실행 · 다형성)
public class AnimalTest {

    public static void main(String[] args) {
        // 다형성: 여러 Animal 하위 타입을 동일하게 처리
        Animal[] animals = {new Cat(), new Dog()};

        for (Animal animal : animals) {
            animal.breathe();
            // animal.cry();
            animalCry(animal);
        }
    }

    // 동물 울음소리 메서드(다형성)
    public static void animalCry(Animal animal) {
        animal.cry();
    }
}
동물이 숨을 쉽니다.
야~ 옹!
동물이 숨을 쉽니다.
멍멍!

animalCry(Animal animal)는 부모 타입을 매개변수로 받아 어떤 자식 객체든 처리한다. 실제 객체(Cat/Dog)에 맞는 cry()가 호출되는 것이 다형성이다.

3 final 예약어

🎯 학습목표
  • final이 변수·메서드·클래스에 적용될 때의 의미를 구분할 수 있다.

📖 개념 및 설명

대상의미
final 변수값을 바꿀 수 없는 상수
final 메서드자식이 재정의(오버라이딩) 불가
final 클래스상속 불가 (예: String, Integer)
💡 예제
final double PI = 3.14;   // 재대입 시 오류
💡 예제 — static 변수 vs final 상수
public class Constant {
    static int num = 10;              // 클래스 변수
    static final int NUM = 100;       // 상수 선언
    static final double PI = 3.1415;

    public static void main(String[] args) {
        num = 20;
        // NUM = 200;   // 오류! final 상수는 값 변경 불가

        System.out.println(num);
        System.out.println(PI);
    }
}
20
3.1415

static 변수(num)는 값을 바꿀 수 있지만, static final 상수(NUM·PI)는 한 번 정한 값을 변경할 수 없다. 상수 이름은 대문자로 쓰는 것이 관례다.

📖 템플릿 메서드(Template Method)

템플릿 메서드는 추상 메서드나 이미 구현된 메서드를 활용하여 전체 기능의 흐름(시나리오)을 정의하는 메서드입니다. 흐름은 고정하되 세부 동작은 자식이 채우게 하는 방식으로, final로 선언하면 하위 클래스가 흐름을 재정의할 수 없어 정해진 순서가 보장됩니다.

💡 예제 — ① Car 추상 클래스 (템플릿 메서드)
public abstract class Car {
    public abstract void drive();
    public abstract void stop();

    public void startCar() {
        System.out.println("시동을 켭니다.");
    }
    public void turnOff() {
        System.out.println("시동을 끕니다.");
    }

    // 템플릿 메서드 — final이라 자식이 재정의할 수 없음
    public final void run() {
        startCar();
        drive();
        stop();
        turnOff();
    }
}
💡 예제 — ② HumanCar / AICar (세부 동작 구현)
public class HumanCar extends Car {
    @Override public void drive() {
        System.out.println("사람이 차를 운전합니다.");
    }
    @Override public void stop() {
        System.out.println("사람이 브레이크를 밟아 정지합니다.");
    }
}

public class AICar extends Car {
    @Override public void drive() {
        System.out.println("자동차가 자율 주행합니다.");
    }
    @Override public void stop() {
        System.out.println("자동차가 스스로 멈춥니다.");
    }
}
💡 예제 — ③ CarTest (실행)
public class CarTest {
    public static void main(String[] args) {
        System.out.println("===== 사람이 운전하는 자동차 =====");
        Car hisCar = new HumanCar();
        hisCar.run();

        System.out.println("===== 자율 주행하는 자동차 =====");
        Car myCar = new AICar();
        myCar.run();
    }
}

run()의 실행 순서(시동→주행→정지→시동끄기)는 항상 같고, 주행·정지 방식만 자식마다 달라진다. 순서를 바꿀 수 없도록 final로 보호한 것이 템플릿 메서드의 핵심이다.

4 인터페이스 선언과 구현

🎯 학습목표
  • 인터페이스의 개념을 이해한다.
  • implements로 인터페이스를 구현할 수 있다.

📖 개념 및 설명

인터페이스는 모든 메서드가 추상 메서드인 '규격'입니다. 어떤 기능을 제공하는지 명시적으로 선언하며, 구현 클래스는 implements로 실제 코드를 채웁니다. (자바 8부터 디폴트·정적 메서드도 가능.)

💡 예제
interface Calculator {
    int add(int a, int b);
}
class MyCalc implements Calculator {
    @Override public int add(int a, int b) { return a + b; }
}
💡 예제 — CalculatorTest (인터페이스 계산기 실행)
// 정수형 사칙연산 인터페이스
interface Calculator {
    int add(int a, int b);
    int subtract(int a, int b);
    int times(int a, int b);
    int divide(int a, int b);
}

// Calculator를 구현한 클래스
class MyCalculator implements Calculator {
    @Override public int add(int a, int b)      { return a + b; }
    @Override public int subtract(int a, int b) { return a - b; }
    @Override public int times(int a, int b)    { return a * b; }
    @Override public int divide(int a, int b) {
        if (b == 0) {
            System.out.println("0으로 나눌 수 없습니다.");
            return 0;
        }
        return a / b;
    }
}

public class CalculatorTest {
    public static void main(String[] args) {
        // 인터페이스 타입으로 구현 객체 생성(다형성)
        Calculator cal = new MyCalculator();

        System.out.println("덧셈:   " + cal.add(7, 3));
        System.out.println("뺄셈:   " + cal.subtract(7, 3));
        System.out.println("곱셈:   " + cal.times(7, 3));
        System.out.println("나눗셈: " + cal.divide(7, 3));
    }
}
덧셈: 10
뺄셈: 4
곱셈: 21
나눗셈: 2

인터페이스 타입(Calculator) 변수에 구현 객체(MyCalculator)를 대입해 사용한다. 인터페이스가 약속한 add·subtract·times·divide를 구현 클래스가 실제로 채운다.

5 인터페이스와 다형성

🎯 학습목표
  • 인터페이스 타입으로 여러 구현 객체를 다룰 수 있다.

📖 개념 및 설명

인터페이스 타입 변수에 어떤 구현 객체를 대입하느냐에 따라 실행 결과가 달라집니다. 예를 들어 RemoteControl 인터페이스를 Television과 Audio가 각각 구현하면, 같은 리모컨 타입으로 둘 다 제어할 수 있습니다.

💡 예제 — ① RemoteControl 인터페이스

인터페이스에는 상수, 추상 메서드뿐 아니라 자바 8부터 디폴트 메서드·정적 메서드도 둘 수 있다.

package interfaces.remotecontrol;

public interface RemoteControl {
    // 인터페이스 상수 (자동으로 public static final)
    public int MAX_VOLUME = 10;
    public int MIN_VOLUME = 0;

    // 추상 메서드
    public void turnOn();
    public void turnOff();
    public void setVolume(int volume);

    // 디폴트 메서드 (기본 구현 제공)
    default void setMute(boolean mute) {
        System.out.println(mute ? "무음 모드 활성화" : "무음 모드 해제");
    }

    // 정적 메서드
    static void replaceBattery() {
        System.out.println("배터리를 교환합니다.");
    }
}
💡 예제 — ② Television 클래스 (구현)
public class Television implements RemoteControl {
    private int volume;
    private boolean isPoweredOn;

    @Override
    public void turnOn() {
        if (!isPoweredOn) {              // 전원이 꺼져 있으면 켬
            isPoweredOn = true;
            System.out.println("TV를 켭니다. 현재 상태: ON");
        }
    }

    @Override
    public void turnOff() {
        if (isPoweredOn) {               // 전원이 켜져 있으면 끔
            isPoweredOn = false;
            System.out.println("TV를 끕니다. 현재 상태: OFF");
        }
    }

    @Override
    public void setVolume(int volume) {
        if (volume > RemoteControl.MAX_VOLUME) {
            this.volume = RemoteControl.MAX_VOLUME;   // 최대 볼륨 제한
        } else if (volume < RemoteControl.MIN_VOLUME) {
            this.volume = RemoteControl.MIN_VOLUME;   // 최소 볼륨 제한
        } else {
            this.volume = volume;
        }
        System.out.println("현재 TV 볼륨: " + this.volume);
    }
}
💡 예제 — ③ RemoteControlTest (실행)
public class RemoteControlTest {
    public static void main(String[] args) {
        // 인터페이스(부모) 타입으로 객체 생성 (자동 형변환)
        RemoteControl remocon = new Television();

        // 기능 테스트
        remocon.turnOn();
        remocon.setVolume(7);
        remocon.setVolume(-1);    // 최소 볼륨으로 제한
        remocon.setVolume(12);    // 최대 볼륨으로 제한
        remocon.setMute(true);     // 디폴트 메서드
        remocon.setMute(false);
        remocon.turnOff();

        // 정적 메서드는 인터페이스 이름으로 호출
        RemoteControl.replaceBattery();
    }
}

정답 보기

구현이 서로 달라도 동일한 인터페이스 메서드로 일괄 처리할 수 있어, 새 구현이 추가돼도 처리 코드를 바꿀 필요가 없다.

실습 6-5. 고객 상담 전화 배분 프로그램

전화 배분 정책을 Scheduler 인터페이스로 정의하고, 세 가지 정책(RoundRobin·LeastJob·PriorityAllocation)을 구현하세요. 사용자가 R/L/P를 입력하면 그에 맞는 정책 객체를 다형성으로 생성해 getNextCall()·sendCallToAgent()를 호출하도록 SchedulerTest를 작성하세요.

정답 보기 (전체 코드) 
// ① Scheduler 인터페이스
public interface Scheduler {
    public void getNextCall();       // 다음 전화를 가져오기
    public void sendCallToAgent();   // 상담원에게 전화 배분
}
// ② RoundRobin — 순서대로 배분
public class RoundRobin implements Scheduler {
    @Override public void getNextCall() {
        System.out.println("상담 전화를 순서대로 대기열에서 가져오기");
    }
    @Override public void sendCallToAgent() {
        System.out.println("다음 순서 상담원에게 배분합니다.");
    }
}
// ③ LeastJob — 대기가 가장 적은 상담원에게 배분
public class LeastJob implements Scheduler {
    @Override public void getNextCall() {
        System.out.println("상담 전화를 순서대로 대기열에서 가져오기");
    }
    @Override public void sendCallToAgent() {
        System.out.println("현재 상담 업무가 없거나 대기가 가장 적은 상담원에게 할당합니다.");
    }
}
// ④ PriorityAllocation — 우선순위(고객 등급)에 따라 배분
public class PriorityAllocation implements Scheduler {
    @Override public void getNextCall() {
        System.out.println("고객 등급이 높은 고객의 전화를 먼저 가져옵니다.");
    }
    @Override public void sendCallToAgent() {
        System.out.println("업무 skill이 높은 상담원에게 우선 배분합니다.");
    }
}
// ⑤ SchedulerTest — 입력에 따라 다형성으로 정책 선택
public class SchedulerTest {
    public static void main(String[] args) throws IOException {
        System.out.println("전화 상담 배분 방식을 선택하세요.");
        System.out.println("R : 한 명씩 차례로 배분");
        System.out.println("L : 쉬고 있거나 대기가 가장 적은 상담원에게 배분");
        System.out.println("P : 우선 순위가 높은 고객 먼저 할당");

        int ch = System.in.read();   // 배분 방식 입력
        Scheduler scheduler = null;

        if (ch == 'R' || ch == 'r') {
            scheduler = new RoundRobin();          // 다형성으로 생성
        } else if (ch == 'L' || ch == 'l') {
            scheduler = new LeastJob();
        } else if (ch == 'P' || ch == 'p') {
            scheduler = new PriorityAllocation();
        } else {
            System.out.println("지원되지 않는 기능입니다.");
            return;
        }

        scheduler.getNextCall();        // 입력받은 정책의 메서드 호출
        scheduler.sendCallToAgent();
    }
}

핵심: Scheduler scheduler 하나로 세 정책을 모두 담고, 실제 객체에 맞는 메서드가 실행된다. 정책을 추가해도 main()의 나머지 코드는 그대로다 — 이것이 전략 패턴(다형성)의 장점이다.

6 다중 구현 · 인터페이스 상속

🎯 학습목표
  • 한 클래스가 여러 인터페이스를 구현할 수 있음을 이해한다.
  • 인터페이스 간 상속(다중 상속)이 가능함을 안다.

📖 개념 및 설명

클래스는 단일 상속만 되지만, 인터페이스는 여러 개를 동시에 구현할 수 있고 인터페이스끼리는 다중 상속도 됩니다. 이는 구현이 아닌 '형(type)'을 상속하는 것입니다.

💡 예제 — ① WebSearchable 인터페이스
package interfaces.smart_tv;

public interface WebSearchable {
    void searchWeb(String url);   // 추상 메서드
}
💡 예제 — ② SmartTV 클래스 (두 인터페이스 구현)
public class SmartTV implements RemoteControl, WebSearchable {
    private int volume;
    private boolean isPoweredOn;

    @Override
    public void searchWeb(String url) {
        System.out.println("검색 중: " + url);
    }

    @Override
    public void turnOn() {
        if (!isPoweredOn) {              // 전원이 꺼져 있으면 켬
            isPoweredOn = true;
            System.out.println("TV를 켭니다. 현재 상태: ON");
        }
    }
    // turnOff(), setVolume(), setMute(), replaceBattery()도 재정의
}
💡 예제 — ③ 테스트 (다형성 활용)
// 인터페이스 타입으로 객체 생성
RemoteControl remocon = new SmartTV();
WebSearchable searcher = (WebSearchable)remocon;

// 리모컨 기능 테스트
remocon.turnOn();
remocon.setVolume(7);
remocon.setVolume(-1);    // 최소 볼륨으로 제한
remocon.setVolume(12);    // 최대 볼륨으로 제한
remocon.setMute(true);
remocon.setMute(false);
remocon.turnOff();

// 검색 기능 테스트
searcher.searchWeb("www.youtube.com");
searcher.searchWeb("www.naver.com");

// 배터리 교환 (인터페이스의 static 메서드)
RemoteControl.replaceBattery();

같은 SmartTV 객체를 RemoteControl·WebSearchable 두 타입으로 바라보며, 각 인터페이스가 약속한 기능만 골라 쓸 수 있다. 이것이 다중 구현과 다형성의 힘이다.

📖 인터페이스 상속 (형 상속, type inheritance)

인터페이스끼리도 extends로 상속할 수 있습니다. 구현 코드를 물려받는 것이 아니라 '형(type)'만 물려받으므로 형 상속(type inheritance)이라 합니다. 클래스는 단일 상속이지만, 인터페이스는 여러 인터페이스를 한 번에 상속(다중 상속)할 수 있습니다.

💡 예제 — ① X · Y 인터페이스
package interfaces.inheritance;

public interface X {
    void x();
}

public interface Y {
    void y();
}
💡 예제 — ② MyInterface (X, Y 다중 상속)
// 인터페이스 X, Y를 다중 상속한 MyInterface
public interface MyInterface extends X, Y {
    void myMethod();
}
💡 예제 — ③ MyClass (구현) · 테스트
public class MyClass implements MyInterface {
    @Override public void x() { System.out.println("x()"); }
    @Override public void y() { System.out.println("y()"); }
    @Override public void myMethod() { System.out.println("myMethod()"); }
}

// 테스트
public static void main(String[] args) {
    MyClass myClass = new MyClass();

    X x = myClass;      // 자동 타입 변환
    x.x();
    Y y = myClass;
    y.y();

    // X, Y를 상속한 MyInterface 타입으로 모두 접근
    System.out.println("** 다중 상속한 iClass 출력 **");
    MyInterface iClass = myClass;
    iClass.myMethod();
    iClass.x();
    iClass.y();
}
x()
y()
** 다중 상속한 iClass 출력 **
myMethod()
x()
y()

MyInterface는 X·Y를 상속했으므로, MyInterface 타입 하나로 x()·y()·myMethod()를 모두 호출할 수 있다.

클래스는 상속을 하나만 받을 수 있지만, 인터페이스는 몇 개까지 구현할 수 있나요?

정답 보기

개수 제한 없이 여러 개를 구현할 수 있다(implements A, B, C).

실습 6-7. 인터페이스 상속 — 스마트폰 만들기

전화 기능 Phone(call())과 카메라 기능 Camera(takePhoto()) 두 인터페이스가 있습니다. 이 둘을 다중 상속한 SmartPhone 인터페이스(installApp() 추가)를 만들고, 이를 구현한 Galaxy 클래스를 작성해 세 기능을 모두 출력해 보세요.

정답 보기 
interface Phone  { void call(); }
interface Camera { void takePhoto(); }

// Phone, Camera를 다중 상속
interface SmartPhone extends Phone, Camera {
    void installApp();
}

public class Galaxy implements SmartPhone {
    @Override public void call()       { System.out.println("전화를 겁니다."); }
    @Override public void takePhoto()  { System.out.println("사진을 찍습니다."); }
    @Override public void installApp() { System.out.println("앱을 설치합니다."); }

    public static void main(String[] args) {
        SmartPhone phone = new Galaxy();
        phone.call();
        phone.takePhoto();
        phone.installApp();
    }
}
전화를 겁니다.
사진을 찍습니다.
앱을 설치합니다.

SmartPhone 하나가 Phone·Camera를 상속했으므로, SmartPhone 타입 변수로 세 기능을 모두 쓸 수 있다.
